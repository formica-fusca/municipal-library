## Why a library?

The target modelled business was about _book reservation, stocks and inventory management_. A lending
library is the sharpest version of that problem, because it forces a distinction
most inventory systems get to avoid: _the library must know **which copy** you have at home_.

A bookshop does not. A customer buying _Dune_ does not care which of the four
boxed copies they receive, and the shop has no reason to track it. That single
difference produces two completely different models of the word "stock" — and
that contrast is the spine of this repository.

<CardGrid>
  <Card title="The library" icon="open-book">
    Stock is a **set of identified volumes**. `BookStock` is an aggregate root
    holding `Copy` child entities, each with its own barcode and its own
    lifecycle: lent, damaged, repaired, lost, withdrawn.
  </Card>
  <Card title="The shop annex" icon="seti:shell">
    Stock is **two integers**. `StockItem` has no children at all, because
    nobody ever asks which unit they bought. Deliberately anaemic — by correct
    modelling, not by accident.
  </Card>
</CardGrid>

## The context map

<Mermaid
  caption="Dotted arrows are domain events. Thick arrows are ports that Lending declares and the composition root implements."
  chart={`

    subgraph LIB["The library"]
        CAT["<b>Catalogue</b><br/>Title"]
        INV["<b>Inventory</b><br/>BookStock ─ Copy*"]
        LEND["<b>Lending</b><br/>Loan · HoldQueue ─ HoldRequest*"]
        MEM["<b>Membership</b><br/>Member"]
    end

    subgraph SHOP["The shop annex"]
        SI["<b>Shop Inventory</b><br/>StockItem"]
    end

    INV -. "title-became-available" .-> LEND
    LEND -. "loan-opened / loan-closed" .-> MEM
    LEND == "ShelfGateway (port)" ==> INV
    LEND == "BorrowerDirectory (port)" ==> MEM

    CAT --- K
    INV --- K
    LEND --- K
    MEM --- K
    SI --- K

`}
/>

`*` marks a **child entity**, living inside its aggregate root's boundary.

There are no other connections. No bounded context imports another, and `tsc -b`
enforces it — the contexts do not list each other as dependencies, so an import
would not even resolve.

## Quick start

<Steps>

1. Install and build.

   ```bash
   pnpm install
   ```

2. Run the six narrated walkthroughs.

   ```bash
   pnpm scenarios
   ```

   Or one at a time — `pnpm scenario:5` is the one that answers the
   entity-emits-events question.

3. Run the tests. Every documented invariant has one.

   ```bash
   pnpm test
   ```

</Steps>
